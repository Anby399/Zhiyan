# 最小 RAG 项目文字流程

本文对应当前代码及 `config.toml` 默认参数，配合 [项目流程图.pdf](项目流程图.pdf) 阅读。PDF 共四页：项目总览、资料导入、问答与缓存、混合检索与精排。下文描述程序行为，不代表已经执行真实服务联调。

## 1. 项目目标与总体数据流

项目把 PDF 资料转换为可检索的知识库。提问时先查询缓存，未命中则进行语义与关键词双路检索，融合候选后再用模型精排，最后让语言模型依据资料生成带引用的回答。

```text
配置加载与校验 → 命令分派
  sample：生成教学 PDF
  ingest：PDF → 分块 → BGE-M3 → MySQL / Milvus → 发布导入版本
  ask：校验导入版本 → Redis 缓存 → 混合检索 → 精排 → ChatOpenAI → 展示与缓存
```

项目采用单人、串行 CLI 操作，没有 Web 服务或 Agent 循环。`ingest` 是全量重建，不是增量上传。

## 2. 组件与模块职责

| 模块或组件 | 输入 | 处理与输出 |
| --- | --- | --- |
| `main.py`、`rag_demo/cli.py` | 命令行参数 | 分派到 sample、ingest 或 ask；`rag.py` 保留兼容入口 |
| `rag_demo/config.py` | `config.toml`、环境变量及 `.env` | Pydantic `Config` 校验参数，导出配置对象及兼容字典 |
| `rag_demo/sample.py` | 固定的教学知识点 | 生成五页 `data/demo.pdf` |
| `rag_demo/loaders.py` | PDF 目录 | PyMuPDF 逐页提取，分块后返回 id、source、page、text |
| `rag_demo/models.py` | 文本或“问题、片段”对 | 加载 BGE-M3 编码器和 BGE reranker，按需复用模型 |
| `rag_demo/stores/mysql.py` | 数据库连接配置 | 建表、提供连接，保存片段原文及来源 |
| `rag_demo/stores/vector.py` | Milvus 连接及向量配置 | 建立 dense / sparse 字段、BM25 函数和索引 |
| `rag_demo/stores/cache.py` | Redis URL | 提供 Redis 连接，读取版本和缓存答案 |
| `rag_demo/retrieval.py` | 问题 | 双路召回、WeightedRanker 融合、MySQL 回表、BGE 精排 |
| `rag_demo/pipeline.py` | PDF 目录或问题 | 编排导入及问答流程，负责发布就绪版本和缓存答案 |

## 3. 启动与配置流程

1. 在项目根目录激活 `lang_env`。项目使用 Python 3.11+，由标准库 `tomllib` 解析 TOML。
2. 执行命令时，CLI 导入相关模块，`config.py` 根据自身文件位置定位项目根目录。
3. `load_dotenv` 读取根目录 `.env`；已有系统环境变量优先，不被 `.env` 覆盖。
4. `Config.load()` 读取 `config.toml` 的 pdf、models、retrieval、storage、llm 五个配置段。
5. 非空 `EMBED_MODEL`、`RERANK_MODEL`、`DEVICE` 覆盖 TOML 中对应模型配置，然后统一交给 Pydantic 校验。
6. 校验包括严格字段类型、未知字段、空字符串、正数与范围约束，以及分块重叠小于块大小、权重不全为零、top_k 不超过 fusion_k 等关系。
7. 合法配置实例供后续模块使用。校验失败会抛出带字段路径的 `ValidationError`，在连接服务或加载模型前停止。
8. MySQL、Redis、Milvus 的地址和账号，以及 OpenAI 密钥、模型名和 API 地址，由对应模块从环境变量读取。它们当前没有全部纳入 Pydantic `Config`，不能把 TOML 校验理解为所有连接配置均已校验。

### 默认教学参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `pdf.chunk_size` / `chunk_overlap` | 500 / 80 字符 | 控制片段大小及边界上下文重叠 |
| `models.embedding` | `BAAI/bge-m3` | 生成 1024 维 dense 向量 |
| `models.reranker` | `BAAI/bge-reranker-v2-m3` | 对问题和候选原文进行精排 |
| `models.device` / `batch_size` | cpu / 8 | 控制推理设备及编码批量 |
| `models.reranker_max_length` | 1024 tokens | 精排输入长度上限 |
| `retrieval.recall_k` | 10 | 每路最多召回 10 条 |
| `retrieval.fusion_k` / `top_k` | 10 / 3 | 融合最多保留 10 条，精排最多保留 3 条 |
| `dense_weight` / `bm25_weight` | 0.6 / 0.4 | WeightedRanker 的两路权重 |
| `storage.ingest_batch_size` | 16 | 每批处理的片段数 |
| `storage.cache_ttl` | 3600 秒 | 相同问题答案的缓存时间 |
| `llm.temperature` / `timeout` / `max_retries` | 0 / 60 秒 / 1 | 控制语言模型调用 |

修改配置后重新执行命令生效。修改分块方式、编码器或向量维度相关行为后，应重新导入资料。

## 4. 基础服务流程

执行 `docker compose up -d --wait --wait-timeout 240` 启动演示服务。

- MySQL 保存原文、文件来源和页码，主机端口为 3306。
- Redis 保存导入就绪版本和问答缓存，主机端口为 6379。
- Milvus 提供 dense 与 BM25 sparse 检索，主机端口为 19530。
- etcd 和 MinIO 是 Milvus 的基础依赖，不是另外两路检索。Milvus 等待两者健康后启动。
- MySQL、etcd、MinIO、Milvus 使用命名卷保存数据；Redis 未显式配置持久化，重启后可能需要重新导入以恢复就绪标记。

这些对外服务端口绑定到 `127.0.0.1`，默认账号用于本地教学。

## 5. 示例资料生成流程：sample

命令：`python main.py sample`。

1. 创建项目根目录下的 `data` 文件夹。
2. 使用 PyMuPDF 创建 PDF，每个知识点单独放在一页。
3. 使用内置中文字体写入标题和正文。
4. 保存为 `data/demo.pdf` 并输出路径。

该步骤只创建资料，不调用 MySQL、Redis、Milvus 或语言模型。

## 6. 资料导入流程：ingest

命令：`python main.py ingest`；默认处理 `data`，也支持传入其他 PDF 目录。

### 6.1 读取与分块

1. `pipeline.ingest()` 调用 `loaders.read_pdf(folder)`。
2. 递归查找目录下 `*.pdf`，按固定顺序遍历。
3. PyMuPDF 逐页读取文本，页码从 1 开始保存。
4. `RecursiveCharacterTextSplitter` 优先按段落、换行和中文标点分割；默认 500 字符一块，重叠 80 字符。
5. 为每个片段生成字符串 ID，并保存相对路径、页码和原文。
6. 没有提取到任何片段时立即报错，此时尚未清除已有索引和就绪版本。扫描件需要先经过其他 OCR 流程。

### 6.2 准备存储

1. 获取 MySQL、Redis、Milvus 连接；MySQL 连接函数确保片段表存在。
2. 删除 Redis 的 `teaching_rag:ready` 标记。标记删除后，该串行演示流程不接受新的问答。
3. 如果已有 `teaching_rag_chunks` collection，先删除，再按 schema 重建。
4. Milvus 字段包括 `id`、启用 jieba 分词的 `text`、1024 维 `dense` 和 `sparse`。
5. 注册 `text → sparse` 的 BM25 函数；dense 建 COSINE 索引，sparse 建 BM25 稀疏倒排索引。
6. 清空 MySQL 的 `teaching_rag_chunks` 表，准备写入完整的新资料。

### 6.3 批量编码与双库存储

每批最多 16 个片段，按以下顺序执行：

1. `models.embed()` 调用 BGE-M3 的 SentenceTransformer 编码器，生成归一化 dense 向量；内部默认编码批量为 8。
2. 先写 MySQL，保存 `id`、`source`、`page`、`text`。
3. 再写 Milvus，保存相同的 `id`、`text` 和 `dense`。
4. Milvus 内置 BM25 函数根据 text 自动生成 sparse，无需 Python 端提交该字段。
5. 重复处理后续批次。两库通过同一 ID 关联，不提供跨库事务。

### 6.4 发布导入版本

1. 所有批次成功后，执行 Milvus `flush`。
2. 生成随机 UUID，写入 `teaching_rag:ready`，作为当前资料版本。
3. 输出导入的片段总数。新的资料版本使此前的问答缓存键失效，旧答案不会被复用，但旧缓存记录直到 TTL 到期才清除。
4. 删除 ready 后任何步骤失败，都不会发布新 ready；修复问题后重新运行导入。若错误发生在删除 ready 之前，则旧标记可能仍保留。

## 7. 问答与缓存流程：ask

命令示例：`python main.py ask "WeightedRanker 和 BGE reranker 有什么区别？"`。

1. 读取 Redis 就绪标记。不存在则报错，要求先成功导入；该标记不是对所有依赖健康状态的检查。
2. 使用“资料版本、问题、OpenAI 模型及地址、两个 BGE 模型配置、全部 TOML 配置”生成 SHA-256 缓存键。
3. 查 Redis。命中时直接输出缓存答案及原文，显示 `[Redis 缓存命中]`，跳过检索与模型推理。
4. 未命中时调用 `retrieval.retrieve(question)`，执行下一节的混合检索与精排。
5. 如果没有可用片段，输出“没有检索到资料。”并结束，不调用语言模型，也不缓存这个结果。
6. 按精排后的顺序，把参考片段组织成 `[1] 文件名 第n页` 加原文的上下文。
7. 创建 `langchain_openai.ChatOpenAI`，使用 `.env` 或系统环境中的 API 配置，并应用 TOML 中的调用参数。
8. system 消息要求仅依据资料作答、使用编号引用、资料不足时说明，并将资料中的指令当作数据；human 消息包含参考资料与用户问题。
9. 调用模型后，拼接“答案 + 参考片段”，写入 Redis，默认保留 3600 秒，然后输出。
10. API 或 Redis 操作异常会向外抛出。本例没有失败时的离线回答或缓存降级机制，也没有实现引用正确性的自动校验。

## 8. 混合检索与精排流程

### 8.1 两路候选召回

`retrieval.py` 构造两个 `AnnSearchRequest`，交由同一次 Milvus `hybrid_search` 执行：

- **语义路**：BGE-M3 编码问题，使用 dense 字段与 COSINE 相似度，最多召回 10 条。
- **关键词路**：提交原始问题字符串，Milvus 根据文本分析及 BM25 函数查询 sparse 字段，最多召回 10 条。

构建请求时，Python 先编码问题；两路检索由 Milvus 在混合查询中完成，并不是 Python 创建了两个异步任务。

### 8.2 WeightedRanker 加权融合

Milvus 使用 `WeightedRanker(0.6, 0.4)` 对两路搜索分数归一化并加权融合，最多返回 10 个命中。权重顺序对应请求顺序：dense 在前，BM25 在后。

它用于组合两种召回信号，不是 BGE reranker，也不是直接将原始 COSINE 和原始 BM25 分数相加。命中不足 10 条时，返回实际可用的数量。

### 8.3 MySQL 回表

1. 从融合结果中取出片段 ID。
2. 使用参数化 SQL 的 `WHERE id IN (...)` 查询 MySQL。
3. 获取原文、文件来源和页码。`IN` 查询不承诺返回顺序，随后会统一精排。
4. Milvus 没有命中或 MySQL 没有对应原文时返回空列表。

### 8.4 BGE 模型精排

1. 使用 CrossEncoder 加载 `BAAI/bge-reranker-v2-m3`，模型按需加载并在当前进程中缓存。
2. 把每个候选组成一对 `[question, text]`。
3. 调用 `predict()` 得到每个问题和原文对的相关性分数。
4. 按分数降序排列，最多取前三条作为最终参考资料。候选不足三条时使用实际数量；当前没有额外的相关性分数阈值。

> BGE-M3 本身也支持其他检索表示，但本项目只使用它的 dense 输出；本项目的 sparse 来自 Milvus BM25。BGE reranker 负责最终精排，分数用于排序，不解释为经过业务校准的置信概率。

## 9. 数据流转示例

假设某个片段为 `id="8"`，来源为 `lesson.pdf` 第 2 页。

| 阶段 | 数据形态 |
| --- | --- |
| 解析后 | `{id: "8", source: "lesson.pdf", page: 2, text: "原文内容"}` |
| MySQL | 保存上述四个字段，供回表与引用 |
| Milvus 写入 | `{id: "8", text: "原文内容", dense: [1024维向量]}` |
| Milvus 内部 | 依据 text 计算 BM25 sparse，并建立对应索引 |
| 混合命中 | 至少包含命中 ID，Python 用它查回原文 |
| 精排后 | 原片段增加 `score`，用于最终排序 |
| 交给 LLM | 如 `[1] lesson.pdf 第2页` 加原文 |
| Redis | 保存最终答案及引用原文，以问题和资料版本等参数确定键 |

## 10. 课堂演示顺序

```powershell
cd F:\Zhiyan
conda activate lang_env
# 先在 .env 中配置 API；已有文件不要重复覆盖。
docker compose up -d --wait --wait-timeout 240
python main.py sample
python main.py ingest
python main.py ask "WeightedRanker 和 BGE reranker 有什么区别？"
# 相同问题再次提问，观察 Redis 缓存命中。

python -m unittest discover -s tests -v
```

讲解时先看 `pipeline.py` 理解全流程，再看 `loaders.py`、`retrieval.py`，最后展开 `models.py`、`stores/` 和 `config.py`。改变融合权重后重新运行问答，会生成新的缓存键；改变分块或编码器后应重新导入。

## 11. 验证范围与教学边界

- 测试覆盖配置校验、PDF 页码、Milvus schema、缓存命中、失败导入、精排顺序和带引用回答的缓存；外部服务与模型输出使用模拟对象，不能代替端到端验证。
- 不要同时执行 ingest 与 ask；Redis ready 标记不是并发锁，不能阻止已经开始的旧查询。
- MySQL 和 Milvus 写入没有跨库事务，导入失败后应全量重建。
- 没有 OCR、复杂版面还原、增量更新、会话记忆、权限体系、自动引用校验或生产监控。
- 图中条数与参数均指当前默认值；配置调整后以代码及实际配置为准。
